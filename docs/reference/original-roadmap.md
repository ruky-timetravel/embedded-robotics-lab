# 嵌入式与机器人：16周学习路线及项目清单
## 仅有电脑起步版

更新日期：2026年10月18日

当前条件：没有开发板、传感器或底盘，只有电脑。现阶段不购买硬件，先形成可移植的C/C++程序、通信模块、控制仿真与机器人仿真成果。真实外设、电路与实时性能安排在后续有设备时验证。

## 1. 学习主线

C与调试 → PC协议项目 → FreeRTOS官方PC示例 → 电机及双轮底盘的软件仿真 → Linux/C++ → ROS 2与导航仿真。

每周约10–15小时，16周为弹性排期，验收未通过则延长。若同时考研，技术学习可先保留每周6–8小时，并相应延长周期。

前8周主要在现有Windows环境学习；Linux与3D仿真环境等进入相应阶段再配置。没有实际核对电脑配置，不承诺Gazebo的运行帧率或流畅程度；图形仿真吃力时先完成轻量二维仿真。

PC阶段形成的是软件与仿真能力。简历明确写“PC端实现”“FreeRTOS PC移植版”“仿真验证”，后续迁移硬件时再增加实板测试结果。

## 2. 先准备的工具

1. 一个可以编译和调试C/C++的环境。Windows可选择Visual Studio并安装“使用C++的桌面开发”工作负载；已有可用编译器则复用。[S1]
2. Git，用于记录代码变更。
3. Python，用于生成数据、测试、保存CSV和画图；现有环境能用就不重复安装。
4. 浏览器，阅读官方手册与可选的Wokwi仿真。
5. Linux环境、ROS 2、Gazebo以后逐步增加，不作为第一周的前置条件。

VS Code主要是编辑器；要编译C/C++，还需配置编译器与调试工具。当前不自动安装软件、不改动系统配置。

## 4. 项目1：PC端设备通信协议与故障测试系统

优先级：第一必做项目。目的：练C模块化、内存边界、流式解析、状态机与测试。

### 4.1 最小版本：一个程序就能开始

- 用C定义帧格式：帧头、命令、长度、序号、负载、校验。
- 输入一串字节数组或测试文件，解析出命令与数据。
- 用虚拟温度或虚拟轮速作为设备数据，不连接真实传感器。
- 通过命令修改虚拟设备状态、采样间隔，读取状态。
- 把接收、解析、业务处理和输出拆分为模块。

先不配置虚拟串口，不写复杂界面。输入文件和函数调用即可练核心逻辑。

### 4.2 增强版本：虚拟设备与上位机

- C程序充当设备端，Python充当测试/上位机。
- 可以先通过文件回放，再使用本机TCP连接传输字节。
- 传输接口单独封装；将来可把PC接口换为UART接口。
- 有开始/停止、读取状态、修改参数、错误应答和日志。
- Python保存CSV、画图、批量发送测试数据。

本机TCP用于练字节流分段、协议与断线恢复；不能据此声称已经调通UART电气接口或验证串口时序。

### 4.3 建议测试清单

- [ ] 正常帧可以正确解析，响应命令与序号对应。
- [ ] 一帧逐字节输入、一次输入多帧均能处理。
- [ ] 帧头前有杂字节时能恢复。
- [ ] 错误校验、异常长度、半帧、空负载、最大负载有明确处理。
- [ ] 环形缓冲区满了有明确策略与错误计数。
- [ ] 连续运行至少1000个自动化命令用例并记录结果。
- [ ] 故障后仍能解析后续合法帧，程序不越界、不死锁。
- [ ] 复现步骤、协议版本、已知问题和原始日志齐全。

测PC通信时间时，优先测本机请求—应答的往返时间RTT。说明它是本机测试结果，不将其写成MCU控制延迟。

交付物：C源码、协议说明、测试脚本、结果日志、CSV/图、故障定位记录、演示和README。

## 5. FreeRTOS怎样在没有板子时学习

使用FreeRTOS官方Windows移植/模拟示例；官方仓库中有WIN32-MSVC示例。[S2]

学习顺序：

1. 编译运行官方最小示例，先读任务和队列相关代码。
2. 建立采集任务，用函数生成虚拟传感器数据。
3. 用队列把数据交给处理任务。
4. 日志任务输出结果，并处理队列满、超时与停止命令。
5. 对共享参数采用明确同步方法，解释队列、互斥和任务通知的区别。
6. 观察任务的运行/阻塞逻辑，避免用忙等待占满执行机会。
7. 把项目1的业务模块与传输接口分开，逐步放入任务结构。

PC移植版适合学习API、任务与同步逻辑。其执行受宿主操作系统影响，官方明确说明不能达到真正的实时行为。[S3] 不用它测STM32中断延迟、DMA吞吐或硬实时控制周期。

构建示例时记录实际仓库版本与工具链；先按该版本说明跑通最小工程，再增加自己的模块。

## 6. 项目2：电机速度控制与双轮底盘软件仿真

优先级：第二必做项目。无需电机、编码器或驱动板。

### 6.1 单电机版本

- 用简化模型产生虚拟电机速度。
- C编写控制器，Python读取CSV并画图。
- 从P或PI开始，加入输出限幅、积分限幅或其他明确的防饱和方法。
- 比较目标改变、负载扰动、参数变化时的表现。
- 先固定采样时间和模型参数，再做变化实验。

可用的一阶离散模型示例：

a = exp(−dt/τ)

ω[k+1] = a·ω[k] + (1−a)·(K·u[k] − d[k])

约定：dt、τ以秒计且τ>0；u是归一化控制输入；K是与速度单位匹配的增益；d是等效速度扰动。模型只用于教学，不代表真实电机参数或完整动力学。

控制器和被控对象分别封装。仿真每一步执行：设定目标 → 算控制量 → 更新模型 → 记录结果。

使用明确的模拟时间步推进计算。宿主程序运行快慢不等同于MCU的实时控制表现。

### 6.2 双轮二维版本

- 左右轮各使用一个模型与控制器。
- 根据线速度v、角速度ω、轮距L计算左右目标轮速：
  - v_left = v − ωL/2
  - v_right = v + ωL/2
- 根据左右轮运动积分得到x、y和航向角，明确单位、符号和坐标定义。
- 绘制直线、圆弧和原地旋转的轨迹。
- 模拟测量噪声、数据延迟和通信中断，每次先改变一个因素。
- 复用项目1的命令、状态机和日志；通信超时进入规定停车状态。

理想无滑移模型不能证明真实底盘定位精度；仿真时使用的假设应写入报告。

### 6.3 验收材料

- [ ] 开环与闭环对比曲线。
- [ ] 目标速度、模型速度、误差和控制输出随模拟时间变化的图。
- [ ] 至少3组设定值与参数的重复测试。
- [ ] 负载扰动、饱和、反转、通信超时的场景记录。
- [ ] 双轮轨迹图与可复现的参数文件。
- [ ] 解释控制周期、积分饱和、单位转换与模型限制。
- [ ] 清楚区分仿真输出与实测数据。

项目亮点在于自己的控制模块、测试与分析，不以演示界面复杂程度衡量。

## 7. 项目3：ROS 2与Gazebo机器人导航仿真

优先级：进阶。没有实体机器人也可开始，电脑性能和图形环境需实际验证。

可用环境组合之一：Ubuntu 24.04 + ROS 2 Jazzy。Jazzy支持至2029年5月，安装时按官方兼容说明选择环境。[S6]

Linux可以在进入相应阶段后，再评估WSL2、虚拟机或其他方式。3D仿真的图形加速与资源需要单独验证；不在学习C之前先重装系统。

顺序：

1. ROS 2基础：节点、话题、参数、launch。
2. 用自己项目2的模拟轮速发布状态或里程计，理解TF。
3. 按Nav2官方Quickstart运行Gazebo中的示例机器人与导航。[S7]
4. 在已有地图中发送目标点；随后再做建图与保存。
5. 增加任务序列、取消、超时与结果记录。
6. 在不同起终点与障碍场景下重复测试，分析失败原因。

速度消息采用Twist还是TwistStamped，按所用版本和接口配置对齐，不混用不同教程的默认值。

低配置替代：先完成二维轨迹仿真、ROS 2数据发布与RViz查看，Gazebo阶段后移。不需要为此立即购买另一台电脑或GPU。

## 8. Wokwi作为可选补充

Wokwi提供STM32 Blue Pill等仿真模型，可练受支持的GPIO、串口、I²C/SPI等内容。[S4]

截至检索时，Blue Pill模型文档将DMA和IWDG列为未实现，ADC也仅部分支持；不同板卡的仿真能力需要分别核对。[S4]

因此：

- [ ] 在练具体外设之前，先读所选板卡的支持表。
- [ ] 外设尚不支持时，改练协议与业务逻辑，把对应硬件验证后移。
- [ ] 核对所用示例的编程框架；Arduino示例不直接等同于STM32 HAL或寄存器开发。
- [ ] 不把仿真器的限制误判成自己配置错误，反复耗费时间。

Wokwi不是本路线的必需工具。软件协议、FreeRTOS PC示例和控制仿真可在本地完成。

## 9. 以后有硬件时再补什么

完成PC项目后，根据目标岗位与预算决定是否购买一款带调试条件的STM32板。不要先买整套底盘和昂贵传感器。

| PC阶段已有成果 | 实板阶段补充验证 |
| --- | --- |
| 协议解析、环形缓冲、错误处理 | 真实UART、DMA、中断与缓冲交接 |
| 虚拟传感器接口 | I²C/SPI采样、时序和真实故障 |
| FreeRTOS任务与同步逻辑 | 芯片中断优先级、栈/堆资源、实际调度表现 |
| 电机模型与速度控制器 | 编码器、PWM、驱动、电源和实际负载 |
| 机器人仿真与导航 | 标定、轮滑、传感器噪声、通信和实车表现 |

硬件岗位还需要补电路阅读、仪器使用与故障定位。软件仿真可以提前积累能力，实板调试能力仍需之后获得。

## 12. 学习与求职的交付标准

每个项目保留：源码、版本与依赖、设计说明、测试输入、原始日志、曲线、故障记录、复现步骤和简短演示。

能解释自己为何选择某种数据结构、同步方法或控制参数，比堆功能更重要。引用现成示例时说明来源和自己的改动，项目结果标明仿真条件。

本版前期不要求拥有任何板子。16周是推进计划，不是录用保证；硬件与实时能力由后续实板验证补齐。
